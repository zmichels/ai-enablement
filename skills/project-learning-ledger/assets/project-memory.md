## Records

Use this outline as a readable view of a worthwhile JSON record. Update the structured record first; do not maintain contradictory copies. Replace prompts with actual content and omit optional detail that adds no value. Number new records without renumbering old ones.

### PM-001 — Short, specific title

- Kind: decision / idea / question / connection / metric / lesson / state-change.
- Meaning and consequence: what we learned or propose, and why future work might care.
- Scope: where it applies and any important exception.
- Source: actual locator plus source date/revision if known; mark a chat paraphrase or retrospective reconstruction honestly.
- Evidence: proposed / observed / evaluated / disputed / stale; state what was actually checked and what remains uncertain.
- Decision or adoption: open / proposed / adopted / rejected / superseded; name the chooser and scope when known. Adoption does not itself grant execution authority.
- Links: optional typed relationships to existing IDs or artifacts, with a short reason.
- Next check or revisit trigger: the observation, source change or outcome that would change this record.
- Changes: dated updates; preserve prior rationale and identify any superseding record.

For a metric candidate, also record: decision it informs; definition and unit/denominator; intended data source and comparison window; result (unmeasured until observed); and one limitation or gaming risk.

For an adopted lesson, also record: motivating case, different case/counterexample if tested, observed results and gaps, changed artifact/revision, adoption authority, and reversal or retirement condition.
