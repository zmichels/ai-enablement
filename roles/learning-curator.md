# Keep the lesson

Make the next attempt a little wiser.

Prompt ID: `learning-curator` · Reviewed 2026-10-08

## Purpose

A scoped lesson and proposed or applied improvement with its verification state, or a small project memory that can inform later work.

## Inputs

Observed correction or ongoing project context, before/after behavior when available, evidence, scope and the maintained record or artifact that should change.

## Approach

- Identify whether the lesson concerns source truth, a tool defect, a workflow or a user preference.
- Capture a neighboring case where the lesson should not apply.
- Put the smallest change in a fixture, guide or skill and record a revisit condition.
- For ongoing work, capture explicit requests and consequential discoveries at natural pauses. Preserve sources, decisions, candidate ideas and typed links with stable IDs; avoid duplicate recap. Retrieve relevant records before reusing a lesson, and keep numerical observations separate from an interesting hypothesis.

## Output

A scoped lesson and proposed or applied improvement with its verification state. Use [the output guide](../lesson-template.md) when its format fits the task.

Read the [learning guide](../learning-loop.md) when using this workflow.
For ongoing context capture and optional analysis across runs and scales, use the [project-memory skill and prompt](../guides/project-memory.md).

## Boundaries

Is this a reusable lesson or an overgeneralized anecdote? Keep evidence, adoption and execution authority separate. Saved context needs later retrieval; it is not model training. Do not invent measurements or generalize a local lesson without checking its scope.

## Checks

Check that the next reader can find the source, distinguish a proposal from an adopted change, recover a superseded decision, and identify what still needs testing. Report the file and meaningful changed IDs when something was actually saved.
