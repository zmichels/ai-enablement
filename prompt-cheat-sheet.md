# A few useful knobs

You do not need to learn a secret language. Tell the assistant what would make the help useful. [Build your helper](library.html), then adjust as you go.

| If you want… | Try saying… |
|---|---|
| A useful first attempt | “Make a small first version. Mark assumptions I should check.” |
| To learn while doing | “Explain one useful choice as we go. Let me try the next step.” |
| A quicker answer | “Give me the answer first, in five bullets or fewer.” |
| More care | “Check the facts that could change the conclusion. Tell me what remains uncertain.” |
| A tangible idea | “Show me a tiny mockup with made-up data so I can react to it.” |
| A few possibilities | “Give me three genuinely different options, including the simplest.” |
| A second opinion | “Find the weakest part of this draft and suggest a specific fix.” |
| Better questions | “Ask only what would change your answer. Make a labeled assumption for the rest.” |
| Help without action | “Draft it for me; do not send, submit, schedule or deploy.” |
| A particular voice | “Sound like a helpful colleague. Skip the corporate warm-up.” |
| A usable format | “Make a checklist I can use during the task, not a report about it.” |
| A clear boundary | “Use these sources. Say what they do not establish.” |
| Useful project memory | “Keep a small ledger of decisions, ideas and lessons. Notice what would be costly to rediscover; skip routine recap.” |

The [project-memory skill and prompt](guides/project-memory.md) add a structured record, quiet capture, later retrieval and optional analysis of repeated observations.

## A little room to play

The helper library has a **Wild card** button. It picks a visible, editable creative nudge—an analogy, a tiny before/after, a friendly title or an unexpected option. Nothing runs in the background and the choice never changes permissions.

A few more things to try:

- “Explain this as if we were planning a potluck. Then translate the analogy back to the real task.”
- “Give this dry checklist a memorable title. Keep every actual step accurate.”
- “Show me the simplest version I could improve in five minutes.”
- “Ask me to guess the next step, then help me check it.”

Keep playfulness suited to the audience. Sensitive conversations and safety-critical instructions need clarity and care, not a forced joke.

## Words that describe behavior

**Explain** asks for understanding. **Draft** asks for editable content. **Compare** asks for differences and tradeoffs. **Review** asks for gaps and improvements. **Prototype** asks for something to inspect. **Verify** asks for a check against evidence. **Execute** asks for an actual action within the stated scope and available permissions.

These words express intent, not tool access or guarantees. “Verified” should name what was checked; “sent” should mean it was actually sent. MUST, SHOULD and MAY in our authored modules have the [documented requirement meanings](prompt-authoring.md). All-caps text is not a magic override.

A quick mockup can help someone with deep knowledge of the work test an idea while it is still fresh. You remain the person shaping the result. Start small, react to what you see, and learn the next thing along the way.
